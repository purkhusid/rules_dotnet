# rules_dotnet 0.23.0

## Breaking changes

These are the API changes since 0.22.2 that require changes to `MODULE.bazel`,
`BUILD` or `.bzl` files. The commits are in
[v0.22.2...v0.23.0](https://github.com/bazel-contrib/rules_dotnet/compare/v0.22.2...v0.23.0).

### Bazel 9 is required

`bazel_compatibility` is now `>=9.0.0` (was `>=8.0.0`).

### `dotnet.toolchain` no longer takes `name`

The `name` attribute of `dotnet.toolchain` is removed, and a build uses one
SDK: the root-most `dotnet.toolchain` tag picks it. Any module in the graph that
passes `name`, even `name = "dotnet"`, fails module resolution.
([#571](https://github.com/bazel-contrib/rules_dotnet/pull/571))

The `<name>_toolchains`, `dotnet_<platform>` (for example
`@dotnet_x86_64-unknown-linux-gnu`) and `dotnet_apphost_*` repositories are
removed. Use `@rules_dotnet//dotnet:resolved_toolchain` instead of a
per-platform SDK repository.
([#571](https://github.com/bazel-contrib/rules_dotnet/pull/571),
[#574](https://github.com/bazel-contrib/rules_dotnet/pull/574))

```starlark
# Before
dotnet.toolchain(name = "dotnet8", dotnet_version = "8.0.100")
use_repo(dotnet, "dotnet8_toolchains")
register_toolchains("@dotnet8_toolchains//:all")

# After
dotnet.toolchain(dotnet_version = "8.0.100")  # or global_json = "//:global.json"
use_repo(dotnet, "dotnet_toolchains")
register_toolchains("@dotnet_toolchains//:all")
```

### `paket2bazel` is replaced by the `paket` extension

`@rules_dotnet//tools/paket2bazel` is removed, and with it the
`paket.<group>.bzl` / `paket.<group>_extension.bzl` files it generated. A module
extension now reads `paket.lock` directly.
([#558](https://github.com/bazel-contrib/rules_dotnet/pull/558))

```starlark
# Before
main_extension = use_extension("//:paket.main_extension.bzl", "main_extension")
use_repo(main_extension, "paket.main")

# After
paket = use_extension("@rules_dotnet//dotnet:paket.bzl", "paket")
paket.parse(
    dependencies = "//:paket.dependencies",
    lock = "//:paket.lock",
)
use_repo(paket, "paket.main")
```

Repository names and labels are unchanged (`@paket.<group>//<package>`). To run
the Paket CLI, use `bazel run @rules_dotnet//tools/paket -- install`.

`nuget_repo` now ignores the `dependencies`, `targeting_pack_overrides`,
`framework_list` and `tools` keys of its `packages` entries, which are read
from each package's `.nupkg` instead. Files generated by `paket2bazel` still
load, but should be replaced as above.

### Toolchain labels moved to `//dotnet/toolchain`

([#612](https://github.com/bazel-contrib/rules_dotnet/pull/612))

| Before | After |
|---|---|
| `@rules_dotnet//dotnet:toolchain_type` | `@rules_dotnet//dotnet/toolchain:toolchain_type` |
| `@rules_dotnet//dotnet:toolchain.bzl` | `@rules_dotnet//dotnet/toolchain:toolchain.bzl` |

The `dotnet_toolchain` rule and `DotnetInfo` provider in `toolchain.bzl` also
changed. These changes only matter if you declare toolchains yourself or read
`DotnetInfo`:

- `dotnet_toolchain` has a new mandatory `os` attribute (`linux`, `osx` or
  `windows`).
- `DotnetInfo.runtime_files`, `csharp_compiler_files` and
  `fsharp_compiler_files` are depsets instead of lists.
- `DotnetInfo.apphost_path` and `apphost_files` are removed.

### `dotnet/repositories.bzl`

`dotnet_register_toolchains` is removed. The `dotnet_repositories` repository
rule no longer has a built-in table of SDK versions: it now takes the archive's
`url` and `integrity`, and requires `runtime_version` and `runtime_tfm`.
([#574](https://github.com/bazel-contrib/rules_dotnet/pull/574),
[#593](https://github.com/bazel-contrib/rules_dotnet/pull/593))

### Config settings removed from `@rules_dotnet//dotnet`

- The `tfm_<framework>_<rid>` settings are removed. `tfm_<framework>` remains.
- `rid_<rid>` and `rid_compatible_<rid>` exist only for portable RIDs, such as
  `linux-x64`. A `select` on, for example, `rid_ubuntu.22.04-x64` fails.

([#565](https://github.com/bazel-contrib/rules_dotnet/pull/565))

### Rules

- The `dotnet_toolchain` attribute is removed from the C# and F# binary,
  library and test rules. It was never read; delete it.
  ([#571](https://github.com/bazel-contrib/rules_dotnet/pull/571))
- `csharp_binary`, `csharp_library`, `csharp_test`, `fsharp_binary`,
  `fsharp_library` and `fsharp_test` in `@rules_dotnet//dotnet:defs.bzl` are now
  macros that wrap the rules. The rule kind seen by `bazel query` is unchanged.
  Code that uses them as rule objects, for example
  `inherit_attrs = csharp_binary` in a symbolic macro, no longer works.
  ([#577](https://github.com/bazel-contrib/rules_dotnet/pull/577))
